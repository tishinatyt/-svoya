# Теревеньки — загальний чат СВОЯ

Статус: підготовлено; нову production-міграцію ще не погоджено й не застосовано.

Розділ `/club/?section=lounge` з'являється в бічному та мобільному меню. Це один чат для всіх міст. Читання й надсилання доступні учасницям зі схваленою анкетою та фото. Є імена, аватари, перехід до профілю, час повідомлення, перенесення рядка через Shift+Enter, автоматичне оновлення кожні 5 секунд та повернення до нових повідомлень. У неактивній вкладці запити призупиняються. Екран показує останні 100 повідомлень; старіші залишаються у базі. Вкладення й персональні сповіщення не входять до цієї версії.

Повторне надсилання після неоднозначної мережевої помилки використовує той самий UUID. Текст зберігається до підтвердження сервера. Авторка може видалити власне повідомлення, адміністраторка — повідомлення доступної їй переписки. Блокування між учасницями діє й у цьому чаті.

## Межі зміни бази

Єдина міграція: `supabase-svoya/supabase/migrations/20261017160438_svoya_lounge_chat.sql`.

Вона додає лише `public.svoya_lounge_messages`, два індекси, три RLS-політики та обмежені grants. Використовує чинні `svoya_private.is_active`, `blocked`, `owner_visible`, `is_admin`. Читати/писати можуть тільки активні учасниці; відправниця має відповідати `auth.uid()`. Час задає сервер. Гості, анкети на перевірці, призупинені профілі не мають доступу. Максимум 2000 символів; порожні та суто пробільні повідомлення заборонені. Редагування повідомлень не надано.

Чинні таблиці, функції, чати зустрічей і об'єкти PORUCH не змінюються. Production перевірено лише читанням: нової таблиці немає, потрібні допоміжні функції збігаються з локальними. Нові тестові користувачі на production не створюються.

## Перевірки

Пройдені локально: `npm test` (28 тестів), `npm run test:db`, `npm run typecheck`, `npm run build`.

Нові SQL-сценарії перевіряють членство, відсутність доступу гостя, підробку автора/часу/метаданих, блокування в обидва боки, призупинення, видалення, довжину й повторний UUID. Нові React-тести перевіряють відображення тексту без HTML, збереження чернетки, безпечний повтор після втрати відповіді, очищення повідомлень і зупинку запитів після виходу/втрати членства.

Браузерна перевірка `npm run test:lounge:browser` використовує ізольовані відповіді API та тестову сесію; зовнішню мережу заблоковано. Вона не доводить доставку повідомлень у production. Запускається в GitHub Actions; локальний запуск Chromium обмежений середовищем. Знімки й результати — в артефакті `svoya-lounge-preview`.

## Порядок запуску після окремого погодження

1. Повторно перевірити відсутність таблиці й визначення чотирьох допоміжних функцій.
2. Застосувати тільки `20261017160438_svoya_lounge_chat.sql` до `pqasdmiqnlyyjwmmqeyc`. Не запускати baseline, старий каталог міграцій або `db push`.
3. Перевірити наявність таблиці, увімкнення RLS, політики та grants читанням системного каталогу.
4. Об'єднати PR із frontend-зміною; дочекатися успіху `Deploy SVOYA`. Перевірити гостьовий екран за прямим посиланням.

Якщо потрібен відкат інтерфейсу, повернути попередній frontend-коміт. Таблицю залишити, щоб зберегти повідомлення; автоматичного видалення даних не передбачено.
