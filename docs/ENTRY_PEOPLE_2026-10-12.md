# Учасниці та чат у картках зустрічей

Картки справжніх подій і кіл показують до чотирьох аватарів, кнопку повного списку та прямий вхід у вкладку чату. Організаторка позначена окремо й не входить у лічильник зайнятих місць. Натискання на аватар відкриває профіль. Демоприклади не показують несправжніх учасниць або чатів.

Імена й приватні фото доступні схваленим учасницям клубу після входу. Гість бачить кількість і запрошення увійти. Список містить тільки організаторку та підтверджених учасниць; заявки, відхилення, черга й потреба в зустрічаючій не розкриваються. Заявки організаторки перенесені в окрему вкладку «Заявки».

Кнопка «Чат» одразу відкриває обговорення конкретної зустрічі. Для непідтверджених учасниць є пояснення наступного кроку. Права читання/надсилання повідомлень залишаються чинними: організаторка або підтверджена учасниця. Повідомлення завантажуються тільки при відкритому чаті. Список учасниць оновлюється після дій, повернення у вікно та кожні 30 секунд у видимій вкладці.

## Межі бази

Єдина нова міграція: `supabase-svoya/supabase/migrations/20261012093023_svoya_entry_people.sql`. Додає лише функції `public.svoya_entry_people(uuid[])` (invoker) та `svoya_private.entry_people(uuid[])` (identity-bound definer у приватній схемі). Повертає id події/людини, ім’я, шлях першого фото й ознаку організаторки; максимум 100 id подій за виклик, пагінація результату на клієнті. Перевіряє схвалення профілю, статус/доступність події, обидва напрямки блокування. Закриті події доступні лише організаторці/підтвердженій учасниці.

Таблиці, дані, існуючі RLS, Auth, PORUCH та старі міграції не змінюються. Відкат — `supabase-svoya/rollback/entry-people.sql`; видаляє тільки дві нові функції. SQL не застосовується деплоєм фронтенду.

## Перевірка

`npm test` — керовані відповіді API: аватар, повний список, чат, гонка відповідей між подіями, оновлення після виходу учасниці, помилка, вихід з акаунта й очищення таймерів.

`npm run test:db` — ізольований PGlite: організаторка + joined, приховані pending/waitlisted, гості, анкети на розгляді, блокування, призупинення, закриті події, скасування участі, ліміт запиту; відсутність нового доступу до заявок або чату. Реальні користувачі в тестах не використовуються. TypeScript і production build — окремі обов’язкові перевірки.

## Робоче підключення

12 жовтня 2026 застосовано тільки нову міграцію `svoya_entry_people` до чинного SVOYA-проєкту. Перевірено визначення функцій, порожній `search_path`, заборону виклику для anon та порожню відповідь без користувацької ідентичності. Нових попереджень Supabase Security Advisor для цієї функції немає. Наявні зауваження до спільних PostGIS/pg_net та закритих службових таблиць не змінювались.
